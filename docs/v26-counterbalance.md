# v26 全身の役割分担を追加した改善候補

## v25 の残欠点と目視での反復

v25 の重心移動フレームでは胸と骨盤が同方向に傾き、脚も同じ親行列で運ばれていた。嬉しい動作の両腕は同時に開き、上げ下ろしの袖は前腕に同期していた。v26 はこれらを別々の関節・時間応答に分ける。数値の合格だけで完成とはせず、v25の同一シナリオ・画角との比較を残した。

最初の候補は左右の脚の局所回転が裾の境界へ及び、細い黒い線が増える可能性を目視で確認した。脚の局所変形開始をy=1230から1300へ下げ、裾直下は骨盤と同じ変換に戻した。再生成した動画・極値で境界を再確認。腕の初回比較は `review/arm-iteration1.png` に保持。

## 本当に分けた素材と所有範囲

元の `torso_clothing` を胸(y<820)、腹(820〜980)、骨盤側衣装(y>=980)に分割。`legs_static` はx=540を境に左右に分割した。新しい5画像は `runtime/model/body_v26/`。色や肌の描き替えはせず、各組の再合成は元画像と完全一致する。PSDとして `assets/parts/v26/koma_counterbalance_v26.psd` に28グループ・8表情を保存し、独立した画像とメッシュ役割をruntime manifestに反映した。元v19のネイティブバックアップも内包。v22/v25の素材は削除していない。

胸メッシュは可視範囲全体を回転、腹のみが腰へつなぐ変形を担当。切断位置の両側に約20pxの共通変換域を設け、別々の画像でも境界が一致する。骨盤側衣装とスカート上端は骨盤親に固定。左右の腿は裾の下と内側の切断帯を共通変換に保ち、y=1300より下の可視部分だけ異なる股関節方向の追従を行う。透明な余白も元画像の矩形に残し、サンプリングが隣接素材を参照しないようにした。描画順は脚→スカート→胴体服→腕・顔を維持。

## 動作

- 骨盤は体重移動に応じて傾く。胸は小さく逆方向に回転し、別のばねで遅れて落ち着く。親の回転中心も画面下端から骨盤域[555,1100]へ移した。
- 左右の腿には異なる角度と応答速度。上半身の平行移動だけで済ませないが、膝のない素材で大きく脚を振らない。
- 上下動は最大6px。膝・足先が存在しないため、ジャンプではなく左右に荷重を移す軽い弾みとした。胴体の伸縮で高さを稼がない。
- 嬉しい動作の左右の腕は開始時刻と振幅をずらす。肩の慣性も胸の角速度を用いて左右で別に計算。
- 頬へ上げる腕は前腕を剛体に保つ。手首に小さな返し、袖口の布だけに中間姿勢の湾曲、垂れる袖には独立した遅れを追加。肘・手首の骨長は維持。
- 頭・12房の髪は既存の身体加速度駆動を維持。顔・目・口・肌色・衣装デザインは変更していない。

## 検証

174 Nodeテスト成功。独立パーツの接続帯、裾直下の一致、胸と骨盤の逆回転、左右の腿の時間差、袖の遅れ、腕骨長、全1024制御隅角、面反転、20〜120fpsの動作を含む。

専用headless Chromeで約18.3秒の動画を生成し、10時刻を実際のMP4からデコード。落ち着いた待機→左右の体重移動→停止→軽い嬉しい弾み→停止→頬への手の上げ下ろし→収束を収録。v25も保存コミットのコードとモデルから読み込み、同じシナリオ・カメラ・黒白背景で比較した。

30フレームの姿勢と8表情×2極値を保存。画面端の切れ0、ブラウザーエラー0。静止時の最終描画はv25から変更値0。8表情の顔テクスチャも変更値0。PSDは再読込後の合成差0、元画像の分割再合成差0。

複合入力の計測では胸の可視区間の長さ変化は0.000109px、胸〜腰は最大0.160px。左右の腿角度差は最大1.346度。計測した関節点の60fpsでの最大移動は0.866px/フレーム。これらは自然さを保証する数値ではなく、急変や伸縮の診断値。

目視資料：`review/body-comparison.png`、`review/arm-comparison.png`、`review/expression-extremes-black.png`、白背景版、動画デコード画像。胴体の棒状の傾きと腕の同期は減っている。衣装長さと腰接続は保たれている範囲で、下半身に追従差が加わった。

## 実際に残る課題

膝・足先・隠れた腿の作画がないため、接地した膝曲げ、足踏み、実際の跳躍は未実装。左右の腿の独立運動は安全のため小さい。脚の大きな従来の透明切り抜きと髪の白いマットは残る。

腕は袖の時間差・布の湾曲・手首の返しを改善したが、中間姿勢の前腕輪郭と袖口の絵の硬さは完全には解消していない。袖の形状を姿勢ごとに描き直す追加作画はまだ行っていない。自然さは主観を含むため、このv26は比較可能な改善候補として扱い、ユーザー評価前に完全な完成とはしない。
