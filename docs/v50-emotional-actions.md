# v50 感情としぐさの連動

基点はv49 `474c8cb7699730581f71ae154fa4a116bdeeaae5`。既存の18.5秒の演技制御とサーバー共有時刻を継続使用する。

- 喜ぶ: 既存joyfulのため・弾み・重心移動に、微笑み→笑い目→微笑みを合わせる。口の形は既存表情画。音声や手動の開口入力を上書きしない。
- 考える: curiousの身体・頬添えの軌道を再使用し、先行する外向き視線と少し下向きの眼球移動を追加。顔は剛体2Dロールだけ。curiousの従来入力は維持。
- 驚く: 既存の驚き表情に、小さな荷重移動・沈み・肩の反応を組み合わせ、微笑みを経て中立へ戻す。新しい脚や奥行き画像は作らない。

## 切替と優先順位

通常UIのしぐさ選択は演技中も使用できる。別しぐさの実行はサーバーが新しい共有epochを発行し、各クライアントは現在のサンプル姿勢から0.6秒のsmoothstepで次へつなぐ。レンダラー/髪物理はリセットしない。同じしぐさの連打はepochを変えない。従来startの重複拒否は保持し、明示switch操作のみ割込みを許可。

停止は最後の実描画サンプルを保持してライブ入力へ減衰復帰する。繰り返す停止通知で別姿勢を再計算しない。視線等の手動スライダーは演技停止、手動表情と口入力は優先。音声・カメラ等によるブロックは従来どおり。配信側は読み取り専用。途中参加は現在の共有時刻へ入って重みを上げ、再接続も時刻を巻き戻さない。

既存の瞬き予定ループは毎回開度を代入し、最後の予定以外を上書きしていた。各予定の閉じ重みを積み重ねる形へ修正し、thinking 1.8秒とsurprised 3.6秒の閉眼を回帰テストに追加。

## 確認動画

23秒・30fps CFR。0秒Joy、6秒Thinkingへ中断切替、14.5秒Surpriseへ中断切替、20秒Stop、23秒まで収束。60Hz固定刻みで制御/髪を進めて30fps画像を出力。全身と原寸顔の2本は同じ入力。白・青緑・黒背景。収録はUIと同じActingControllerを使い、実UI/別コンテキスト同期は別の実時間検証に分ける。

コードテストに加え、笑い目、頬到達、切替前後、完全停止を実画像で検査する。最終結果はreview/report.json、ui-review/report.json、final-tests.jsonを参照。全フレームを生成するが、目視は重点区間と選択姿勢であり、全フレームを一枚ずつ原寸検査したとはしない。

## 維持したものと限界

v49の目描画・原画・PSD、2D顔、腕/胴/腰/スカートの構造は変更なし。新しい顔yaw/pitchコマンドは0。肩素材の水平切断端は既知の未修正箇所。拒否された肩生成は再試行していない。足先/膝の不足から大ジャンプ・真の前後移動は表現しない。驚きは2D内の小さな身引きである。手と頬の接触は見た目の確認で、立体衝突判定ではない。

途中参加の立ち上がり0.6秒前後は既存クライアントと混合履歴が異なる。継続演技の時刻は共有される。headless動画再生のdrop数はCFRの正しさや本番性能とは別に報告する。新規インストール・公開・upload・push・main mergeなし。

## 最終検証結果

JavaScript 221件、runtime Python 98件成功。実UI検証はerrors空、連打・途中参加・思考/驚きへの切替・再接続・手動表情・口手動による停止・明示停止・モード変更を完了。初回の口スライダーtimeoutは検証側が「口の開閉」と誤記していたためで、実在する「口の開き」へ修正後に全経路を再検証した。最終動画は瞬き修正後のコードから再生成済み（validation.jsonでソース更新時刻と収録開始時刻を照合）。

単独headless等速再生は690フレーム、drop 0。この実行条件の結果であり、全端末の実時間性能の保証ではない。

中断なしの追加実画像検証では、各しぐさを0〜21秒まで30Hzで進め、11姿勢×3種類=33枚を保存した。21秒時点は3種類とも重み0・neutralに復帰。exit-review/exit-contact.pngで保持・退場・復帰を比較できる。
