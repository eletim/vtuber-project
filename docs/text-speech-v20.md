# 羽月こま v20: 入力した文章を新しく合成して話す

v19の分離済みの左右の腕・胴体・スカートと、承認済みの顔・口の肌色をそのまま使います。画像とPSDは変更していません。WebGL実装であり、Cubismモデルではありません。

## 今回できること

- 文章を入力し「文章から音声を生成」を押すと、ローカルのVOICEVOXへ実際に合成を依頼します。保存済み音声への代替はしません。
- 音声の実際の再生に合わせて口、表情、控えめな腕・体の仕草が動きます。合成待ちの時間は話し始めません。
- 「音声停止」は合成中も使えます。AI操作モードを維持し、音声と口の動きを停止します。
- 新しい文章へ差し替えたとき、古いリクエストが遅れて戻っても再生しません。OBSオーバーレイは無音で、操作画面だけが再生します。
- 一時停止、シーク、再生速度変更、バッファ待ち、音声エラーを再生状態へ反映します。
- 接続状況を確認でき、エンジン未起動、話者不在、不正な音声、合成失敗を区別します。

## 起動

Python 3.10以降と、WebGL2対応ブラウザを用意してください。エンジンは同梱していません。

1. core.zip と model.zip を同じ場所へ展開し、koma-v20-runtime フォルダーの中身を統合します。
2. そのフォルダーで `python -m pip install -r requirements-runtime.txt` を実行します。
3. すでにVOICEVOXを使っている場合は、エンジンを127.0.0.1:50021で起動します。
4. `python scripts/run_runtime.py --text-only` を実行し、表示された http://127.0.0.1:8766 を開きます。
5. 音声接続を確認し、文章を入力して合成します。ブラウザが自動再生を止めた場合だけ、音声の再生ボタンを押します。

`--text-only` はカメラ用ライブラリのダウンロードだけを省略します。アバター表示、音声合成、表情、仕草は使用できます。カメラ操作が必要なときは同じコマンドから `--text-only` を外して起動し直します。

### 公式の無料Linux CPUエンジンを新しく導入する場合

必要な場合だけ実行してください。Linux x64向けです。Windows/macOSは公式VOICEVOXを別途起動します。

- `python -m pip install -r requirements-voicevox-setup.txt`
- `python scripts/setup_voicevox.py`
- `python scripts/run_runtime.py --text-only --voicevox`

公式0.25.2配布物をSHA256検証して導入します。大きなダウンロードと数GBの空き容量が必要です。自動起動したエンジンのデータ保存先は、このフォルダー内の runtime/vendor/voicevox/user-* です。終了時にはこのコマンドで起動したエンジンも終了します。既存のVOICEVOXを使う場合は `--voicevox` を付けません。

公式配布: https://github.com/VOICEVOX/voicevox_engine/releases/tag/0.25.2
VOICEVOX利用規約: https://voicevox.hiroshiba.jp/term/
雨晴はう利用規約: https://amehau.com/rules/amehare-hau-rule
音声利用時のクレジット: **VOICEVOX:雨晴はう**

## 検証した範囲と未検証の範囲

今回、新しい日本語文章を公式エンジンで実合成し、runtimeのHTTP、WebSocket、音声取得、操作画面だけへの再生指定、再生・停止による表情状態まで確認しました。停止・重複・遅延・切断・エラーは自動テストでも確認しました。

付属の短い動画は、その新しい音声と実際のモーション計算を使ったオフライン描画です。ブラウザの操作録画ではありません。この作業環境では許可されたブラウザ操作経路を利用できず、実ブラウザでのGUI・スピーカー出力の通し確認は未実施です。利用するPCのブラウザで最終確認が必要です。

samples のWAVは今回新しく合成して保存した検証用音声です。これをアップロード再生することは「その場での新規合成」ではありません。新規合成の確認には文章入力ボタンを使ってください。

スカートは安全範囲内の小さな揺れです。大きな手振りや布物理ではありません。以前からの脚の隠れ領域や髪の縁の課題を修正した版ではありません。

## AIの返答との接続状況

まだLLMや会話履歴は接続していません。「AI操作」は操作の入力元の名前で、文章を考える機能ではありません。APIキーの作成・設定や、有料サービスへの送信はしていません。

既存のAIプログラムが返した文章は runtime/ai_client.py の KomaClient.say(text) に渡せます。select('ai') で操作元を切り替え、stop(request_id) で特定の発話を止め、voice_status() で接続を確認できます。返答モデルを選ぶ段階では、利用するローカルモデルまたは既存の許可済みサービス、費用と送信データを決める必要があります。

## ローカルAPI

- GET /api/voice: エンジンと話者の接続確認
- POST /api/speech: text、emotion、任意のexpressionと一意なrequest_id
- POST /api/speech/cancel: request_id付きならその発話だけ、空オブジェクトなら現在の発話を停止
- POST /api/playback: clip_id、state、position、sequence、任意のplayback_rate

停止は未使用の結果を破棄し、再生を止めます。エンジン内部で進行中の計算が即座に止まる保証はありません。

停止済み・重複のrequest_idは再利用せず、新しく発行してください。サーバーは127.0.0.1のみに待ち受けます。公開インターネットへ直接公開するための認証機能はありません。
