# v49: 虹彩下縁の合成修正

基点: v48 `1b04123ebead2581305dacb2379eb587479ff050`。変更は `runtime/web/eye-components.js` の描画計算のみ。原画、PSD、輪郭、表情別座標、瞬き曲線、2Dロール、身体・髪・手のリグは変更していない。

## 再現と原因

比較シナリオ10.33〜10.50秒（310〜315）で、不機嫌の画面左目に明るい下縁が出る。315の要求はthinkingだが、切替開始時の実際の絵はdispleased。単独パッチでも displeased・開度1・視線(-0.84,-0.68)で再現。上の白いハイライトや下の金色反射とは区別した。

虹彩の近似楕円に下まぶたの肌画素が混入し、移動元を固定色(255,249,245)で復元していた。さらに推定alphaが暗い境界色を表現するには低すぎ、負のpremultiplied RGBが生じていた。14目プロファイル全てで不正色を確認。

1. 下方の肌色画素を虹彩の移動対象から外す。
2. 下方の復元色は原画の同じ高さの明るい周辺画素から推定し、上方の白目から連続的に移行する。白一色で下まぶたまで埋めない。
3. 原画色の再合成を保ちながら、有効なpremultiplied RGBを表現できるalphaへ補正する。

最初のalpha補正＋所有範囲だけの候補は下縁の白画素を増やしたため不採用。局所背景色の修正後、再現ROI [114,89,169,108]の白判定画素はv48の38から16へ減った。これは診断の補助値で、目視合格の代用ではない。比較は `iris-probe/rim-diagnostic.png` と `rim-metric.json`。

## 確認範囲

- 実AvatarRendererで8表情×5開度。v45原画の全開中央・完全閉眼16条件は最大RGB差0。
- 7可動表情×左右×61段階、視線の循環入力を同時に与え854パッチを生成。big_smileは原画の笑い目を引き続き使用。
- 7表情×左右の視線中央/上左/上/下/右。原画の左右差を維持。
- v48との同入力比較360フレームと全身サンプル。30fps・12秒CFR、口開閉・実際の頭ロール・身体と手を含む。
- 旧問題の012/022/147/237/247/282/327、および310〜330の連番を重点確認。照れの灰帯、閉眼位置、二重上まつ毛の再発を見ていない。
- 目視は原寸315・パッチ拡大・選択開度のコンタクトシートと重点連番。854枚全てを一枚ずつ原寸目視したという意味ではない。
- 通常UIと別コンテキスト配信画面の視線・再接続・口手動入力優先。8表情の黒背景確認。
- 最終テスト/再生測定結果は `assets/parts/v49/final-tests.json` と `ui-review/report.json` を参照。

## 残る限界

虹彩と下まぶた境界の細かなアンチエイリアス/明るさは拡大で残る。局所背景推定と色分類は現在の原画用で、完全な手描きの独立輪郭に置き換えたものではない。原画の金色反射を消す方向には追い込んでいない。大きな視線幅・新しい絵柄へ一般化した保証はない。

新たな瞬きタイミングの欠陥は確認できなかったため、受け入れ済みの表情切替や瞬き速度を理由なく変更していない。headless等速再生の計測は実施するが、ユーザー画面での主観的な連続再生確認とは区別する。既知の肩切断端は対象外、拒否済み生成も未実行。外部送信・pushなし。

PSDはv47の原画パーツを継続使用。SHA256 `10dcb1d4e03f58153074c37ec48f54a552cc8fb708fb41e56380a540c7d2c77e`、27,075,106 bytes。今回の変更は描画時のマスク/背景復元計算であり、PSDの画素を変更する必要はない。
